PLAN DE INTEGRACION WEB Y BOTS

Abrir primero PLAN_INTEGRACION_WEB_BOTS.md, en la carpeta superior.
openapi.json: contrato propuesto OpenAPI 3.1 para importar en herramientas de API.
ejemplos.json: cuerpos de peticion/respuesta y ejemplo multipart.

Es una propuesta de implementacion, no un anuncio de endpoints ya habilitados.
No se ha modificado el backend para preparar estos documentos.
IDs, usuarios, hashes y dominio de los ejemplos son ficticios.
Los hashes ilustrativos no corresponden a archivos binarios de prueba.

Regla principal: solicitud_id = ejecucion_id = ID seleccionado en la web.
Solo EN_COLA puede iniciar; no se reutiliza la ultima solicitud.
El operador decide donde lanzar el bot. Al comenzar, el bot envia
POST /api/bot/ejecuciones/siguiente solo con solicitud_id y ejecucion_id.
Ambos IDs son obligatorios e iguales. La ruta nunca selecciona otra solicitud.
Esta adaptacion sustituye el comportamiento heredado de siguiente;
no devuelve 204 ni reutiliza trabajo cuando el ID no puede ejecutarse.
Espera la confirmacion antes de descargar el input o ejecutar el negocio.
El input es opcional segun el proceso. Si existe, descargarlo por HTTP
despues de iniciar y verificar tamano y SHA-256 antes de procesar.
El reporte se entrega como archivo multipart con metadatos JSON.

El login utiliza sesion Django y CSRF; no refresh JWT.
La propuesta exige sesion y clave individual en las rutas del bot,
y CSRF en los POST. Esto requiere cambios en backend Y bots.

El OpenAPI describe el contrato bot/autenticacion. Las operaciones humanas
de crear/liberar solicitudes estan explicadas en el plan y siguen separadas.
